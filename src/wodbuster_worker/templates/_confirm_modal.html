{# Reusable confirmation modal. Renders a hidden dialog plus an inline script that installs ONE delegated submit listener on the document. Any form that wants to ask for confirmation before submitting declares a data attribute: data-wb-confirm="{{ t('some.key') }}" The value is TEXT, not code, so Jinja's autoescape is exactly the right treatment: an apostrophe or a quote in the copy becomes an entity, the HTML parser decodes it back, and the message reaches the listener intact. Nothing is ever parsed as JavaScript, which is what the earlier inline-handler form required and what made a single apostrophe able to silently disable the confirmation. Keeping the templates free of JavaScript also keeps the editor's TypeScript analysis away from Jinja delimiters, which it reports as syntax errors when they appear inside an event attribute. The listener cancels the first submit, opens the modal, and re-submits the form when the operator taps Confirm. Uses the native dialog element (baseline available in every modern browser as of 2023+); no external JS dependency. Falls back to the browser confirm() when dialog is missing. #}
